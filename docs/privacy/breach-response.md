# Personal-data incident response

1. **Contain:** restrict access, rotate exposed credentials, disable the affected route/integration if needed, and preserve minimal relevant evidence.
2. **Assess:** identify the data categories, affected individuals, time window, systems/processors, likely cause, and potential impact.
3. **Remediate:** remove the exposure, patch the cause, review provider logs, and verify the fix.
4. **Communicate:** obtain appropriate legal/security advice on notification obligations. Use the current applicable DPDP Act/Rules phase and any other law; do not promise a statutory timeframe without that assessment.
5. **Document:** record the incident, decisions, communications, and corrective actions in a restricted internal record.
6. **Learn:** review code, access, processor settings, retention, and runbooks to prevent recurrence.

Never disclose visitor personal data, secret values, stack traces, or internal security details in a public incident notice.
